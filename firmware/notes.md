General comments:
- Each core is siloed as follows:
  - Core 0 handles USB/serial communication, maintains stimjim_context, and
    transmits messages to core1 through queues or doorbells.
  - Core 1 handles pulse timings and maintens two stimulus_contexts as well as
    any ADC/DAC interaction
- Core1 uses timer0 for pulse timing. Timer0 increments on a hardware peripheral
  tick generator which ticks every microsecond by default.
- Non-blocking SPI is implemented with PIO. Each PIO has two state machines -
  one for ADC @ 10MHz and one for DAC @ 30MHz. A state machine is
  enabled/disabled depending on which device we are trying to communicate.
- GPIO interrupts are enabled/disabled by core 0 when corresponding commands are
  received from the user. If channel 0 and channel 1 assert at the same clock
  cycle, channel 0 takes priority.
- Doorbell interrupt registers are polled to cancel pulse trains (no
  ISR/callback).
- Wrapping a function in "__time_critical_func()" can avoid latency from cold
  cache i.e. if data or code is not loaded from flash into SRAM yet. Only ISRs
  and the main_core1 function are attributed as time critical (all the functions
  it directly calls are inlined).
