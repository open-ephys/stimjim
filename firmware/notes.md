General comments:
- There are many extra optimization attempts, I have to go 1-by-1 and see which
  actually matter.
- Is my queue structure sufficiently deterministic?
- Timers are polled to generate pulse timings. These timers use microsecond
  tick generators as their clock source by default.
- Each core is assigned timing for each core. Access to respective hardware
  peripherals is siloed into a single core. Core0 has additional
  responsibilities of: handling UART, maintaining context, and driving core1.
- GPIO interrupt registers are polled to trigger pulse trains (no ISR/callback).
- Doorbell interrupt registers are polled to cancel pulse trains (no ISR/callback).  
- Wrapping functions in "__time_critical_func()" can avoid latency from cold
  cache i.e. if function is not loaded from flash into SRAM yet. This macro
  wraps some functions to prevent the first stage in the first delivered
  pulse train from lagging when the first stage is short, like ~20us.

Changes from previous stimjim_teensy:
- Channels float after delivering a stimulus.
- Stimuli are cancelled when a command is received.
- User input strings are validated (adds a ton of cruft to code?)
- Some printouts might not be exactly the same.
- Voltage offsets are calculated on boot.
- Intentional fall-through from B to C command. You can no longer just calculate
  ADC offsets, if you do that, it automatically goes to calculate all offsets.
- Removed 2.5V range calibration. The og stimjim calibrated using this and then
  operates in 10V mode, but the 2.5V and 10V calibrations are different.
- Pulse train logic might be a little different
